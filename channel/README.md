# A ↔ B 沟通通道

这个目录是 A 侧与 B 侧（含双方 agent）的**异步对话通道**。
一条消息一个 markdown 文件，git 提交即送达。

---

## 目录约定

```
channel/
  README.md      本文件：协议。双方都可改，但改动要同时在各自 STATE.md 里说明
  A/             只有 A 写
    STATE.md     A 的当前状态：已读到哪封、在办什么、承诺了什么
    001_*.md     消息，序号递增
  B/             只有 B 写，规则同上
    STATE.md
```

## 规则

1. **只写自己的目录。** 绝不修改对方的文件 —— 既避免冲突，也保证"谁说的"可追溯。
2. **一条消息一个文件**，命名 `<三位序号>_<YYYYMMDD>_<短标题>.md`，序号在各自目录内递增。
3. 每封开头写一行元信息：

   ```
   > 发件：A | 日期：2026-10-25 | 回复：B/002_…（可空）| 状态：待回复 / 已结案
   ```

4. **收到新消息后**：先读对方 `STATE.md` 看全貌，再在自己 `STATE.md` 里登记
   `已读 <文件名> @ <commit 短 hash>`，然后回信。
5. **结案**：把该封开头的状态改成 `已结案`，并在自己 `STATE.md` 里划掉。
6. **结论靠实验，不靠讨论**。谁提结论，谁给三样东西：命令 / 输入 md5 / 期望输出 md5。
7. **数字必须标口径**：实测 / 推算 / 未验。没有口径的数字当没写。
8. **不能直接 push 的一方**：把 md 交给能 push 的一方代提交（或开 PR / issue），
   提交信息里注明原作者。代提交不改内容。

## 怎么知道有新消息

```bash
git pull
git log --oneline -5 -- channel/
ls channel/B/     # B 有新文件就会出现你没登记过的名字
```

## 时间与版本

时间一律用 **Asia/Shanghai**，写完整日期。跨天的工作在消息里写明"截至 <日期>"，
不要用"今天/昨天"这种相对说法 —— 双方读到的时刻不同。
