## 2. 实验一：同符号 / 同 CDF，PL vs CPU（你们点名要的）

板端 `/root/glc/pack/glc2_pack` 是 **A53 CPU 的 rANS 实现**，与 PL 是两套独立代码。做法：

1. daemon 编一张图（t1 = IMG_0036 的无损 PNG），**同一时刻**冻结它落下的操作数
   （`p{k}_sym.i32`、`p{k}_scales.f32`、`p{k}_means_raw.f32`）；
2. 把这批操作数**原样**喂给 `glc2_pack`；
3. 逐字节比较。

```
PL  rANS 容器 : /root/pl_t1.glc   292 B  md5 e9b07f13c65186fb461b377b5f024d28
CPU rANS 容器 : /root/cpu_t1.glc  292 B  md5 e9b07f13c65186fb461b377b5f024d28
cmp: 逐字节相同 ✅
```

`glc2_pack` 自己的输出也印证了四段长度：56 / 48 / 44 / 40，与容器头一致，`用到 CDF 行 16/64`、`escape 0、bypass 0`。

⇒ **PL rANS 写出的字节与 CPU rANS 完全一致，PL 可以排除。**

## 3. 实验二：解码端符号 vs 编码端符号（独立逐符号对照）

你们要"独立逐符号解码对照"。板端编码时会落 `p{k}_sym.i32`（**送进 rANS 之前的原始符号**），
我们拿它和"用 int8 `_ZG` 先验解容器得到的符号"逐位比：

| 相位 | 符号逐位相同 | scales（全张量） | means（全张量） |
|---|---|---|---|
| 0 | **16384/16384** ✅ | **65536/65536** ✅ | **65536/65536** ✅ |
| 1 | **16384/16384** ✅ | **65536/65536** ✅ | **65536/65536** ✅ |

⇒ **编码端与解码端的操作数逐位相同**。容器里的符号就是编码端那一批，一个都没错。

（旁证：板端 `/root/glc/consts/` 的 `z_codebook.npy`／`ysp_reduce_w.npy`／`ysp_reduce_b.npy`

## 4. 实验三：把 latent 本身拿出来比

既然符号和 means 都对，latent 就是唯一还能出错的地方。板端 latent = `(sym + means) × q_dec`；
PC 侧用 **fp32 S1** 对同一张图前向一次：

```
板端 latent（容器重建）: min -1.581  max 1.976  mean  0.002  std 0.088
PC  fp32 S1 latent     : min -1.928  max 1.392  mean -0.003  std 0.085

余弦相似度 = 0.477910
相对 L2    = 1.0408（104.1%）
逐元素 max|Δ| = 2.316
量化步长 q_dec 均值 = 1.156  ⇒ 正常量化误差应在 ½ 步量级（~0.5）
```

**两个 latent 的差异和信号本身一样大**（相对 L2 104%），远超量化误差量级。
这不是"精度不够"，是**两个不相干的东西**。

### 4.1 与"有的图能解、有的不能"吻合

| 图 | 容器 | 解出 PSNR |
|---|---|---|
| IMG_0036（原图，偏暗：均值 R76/G75/B58） | 292 B | **8.07 dB**（错） |
| 同图 +16 亮度 | 316 B | **21.37 dB**（对） |
| 同图水平翻转 | 280 B | 7.64 dB（错） |

⇒ **偏暗的输入失败、提亮后成功**。这非常像 **int8 S1 的输入端/首层量化在暗部饱和**。
