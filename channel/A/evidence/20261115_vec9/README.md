## 三条自检

```bash
python verify.py            # 做 ①②
python verify.py --decoded  # ①② + ③（需要 dec_tile01..09.png）
```

| # | 检查 | 期望 | 意义 |
|---|---|---|---|
| ① | 21 个文件 md5 与 `md5sums.txt` 一致 | 全部通过 | 传输没坏 |
| ② | 9 个**源块**按 §5 权重融合 vs `source_512.png` | 最大误差 **≤ 1 LSB**（我方 0.0000） | **几何+权重正确**，与编码器无关 |
| ③ | 9 个**解码块**（你们解出来的）融合 vs 源图 | PSNR **≥ 18 dB**（该图 4 块基线 19.08 dB） | 端到端没搭错 |

> ② 是这份向量的核心：脚本按 `Σw` **归一化**融合，无损块在归一化下**恒等还原**源图。
> 只有重叠区 `Σw ≡ 1`；最外 64 px ramp 带里单块 `Σw < 1`，**靠归一化**才不暗。做不到就说明坐标或权重错了。

## 说明

- 容器由板端 `glc_batch_rsd.py` 逐块编码（`enc_image.py --mode squash`，输入就是 `tile0N.png`）；
  本地 md5 与板端 `md5sum` **9/9 一致**。
- 我们**无法**在 PC 上解码板端容器（NPU BF16 与 PC fp32 数值不同），所以不提供"期望解码图"；
  ③ 的门限按同一张图 4 块基线的 19.08 dB 给出宽松下界 18 dB，只用于判断"有没有搭错"。
- 若 ③ 明显低于 18 dB，优先查：坐标贴错 / 权重没归一化 / LIFT 用了不同的 K。
