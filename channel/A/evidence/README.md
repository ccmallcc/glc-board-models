# A 侧证据文件

| 文件 | 是什么 | 字节 | md5 |
|---|---|---|---|
| `IMG_0036.jpg` | **s085 的原图**（小王子头像，红围巾，中等偏暗）。256×256 RGB，是我们编码器的直接输入 | 21,204 | `38fe5408d2576f2a45c99132c4cac980` |
| `hybrid_IMG0036_316B.glc` | **S1 混合链容器**：fp32 S1 出 y/z + **int8 `_ZG` 算先验** + fp32 S4 出图。0.03857 bpp，我方自解 26.72 dB，PNG md5 `c7c23875…` | 316 | `21654a58efefcecbfdf33a0ad926d53c` |

## 说明

- 这张 256×256 就是编码器读到的**原始输入**，中间没有 resize、没有裁剪。
- 通道均值 **R 76.1 / G 75.3 / B 57.7**，R−G = **+0.8**（基本中性）。
  所以"解出来偏红"不可能是原图带的整体偏红 —— 画面里只有**围巾是红的**。
- 我们本地只有这一份 256×256；比对过 10 张更大的原图（最大 4096×3072），
  没有一张是它的中心裁剪（最高 14.21 dB）。

## `hybrid_IMG0036_316B.glc` 怎么用

请用 **int8 `_ZG` 链**解（fp32 参考链解不了，先验不同源）：

```bash
python3 "AB板/02_A侧代码/07_解码端/工具/pc_decode_selfcontained.py" \
        --glc_dir channel/A/evidence --png_dir <任一含 png 的目录> --n 1 --device cpu
```

期望：解出的图与 `IMG_0036.jpg` 比 **≈26.7 dB**；PNG 若与我们的 `c7c23875…` 逐字节相同，
就说明两边的 int8 先验完全同源。**这个结果直接决定 S1 值不值得上。**

引用时请连 md5 一起引用。
