## 2 帧信封（**A→B 的所有帧**统一；B→A 的应答是 §3 的 3 字节特例）

```
AA 55 | SEQ(1B) | LEN(2B BE) | PAYLOAD(LEN 字节) | SUM(PAYLOAD) & 0xFF (1B)
```

| 字段 | 含义 |
|---|---|
| `AA 55` | 魔数 |
| `SEQ` | `0x00` = 控制帧；`0x01..0xFF` = 数据帧（本会话内第 SEQ 张） |
| `LEN` | **只算 PAYLOAD 的字节数**（不含信封与校验） |
| `SUM` | PAYLOAD 各字节算术和取低 8 位 |

---

## 3 应答（B → A）

| 帧 | 字节 | 含义 |
|---|---|---|
| ACK | `AA 55 06` | 已收到并接受（对控制帧 = 已理解；对数据帧 = 已存好） |
| NAK | `AA 55 15` | 校验失败或拒绝 |

---

## 4 控制帧（`SEQ = 0x00`）

| CMD | 名称 | PAYLOAD |
|---|---|---|
| `0x10` | **SESSION_BEGIN** | `CMD(1) \| N(1) \| MODE(1) \| RATE(1) \| [LEN*] \| [ORIG] \| [LIFT]`（详见 §6） |
| `0x11` | **SESSION_END** | `CMD(1) \| SENT(1) \| OK(1)` |
| `0x12` | **SESSION_ABORT** | `CMD(1) \| REASON(1)` |
| `0x13` | **SESSION_RETRY** | `CMD(1) \| K(1) \| seq_1 .. seq_K` |

**会话流程**

```
A                                                   B
├─ SESSION_BEGIN(N, MODE, LEN*, ORIG, LIFT) ───────►│ 建立会话
│◄──────────────── ACK ─────────────────────────────┤
├─ 数据帧 SEQ=1（容器 / 文字）──────────────────────►│ 存 rx1
│◄──────────────── ACK ─────────────────────────────┤
├─ …… SEQ=2..N ……                                   │
├─ SESSION_END(SENT, OK) ───────────────────────────►│ 汇总、落盘、解码
│◄──────────────── ACK ─────────────────────────────┤
```

---

## 5 MODE 语义

| MODE | 含义 | N | 数据帧 PAYLOAD |
|---|---|---|---|
| `0` | 小图（256×256 一张） | 1 | GLC 容器（`GLC2` 76 B 头 + 码流） |
| `1` | 大图（512×512 切四块） | **固定 4** | 4 个 GLC 容器，顺序 **左上、右上、右下、左下**（顺时针） |
| `2` | 文字 | 1 | **UTF-8 明文**（不要送解码器） |

`RATE` 保留，当前固定 `0`（= 19200 bps 档）。

---

## 6 SESSION_BEGIN 的 PAYLOAD 布局

```
[0]              CMD = 0x10
[1]              N
[2]              MODE
[3]              RATE                    （保留，固定 0）
[4 .. 4+2N)      LEN_0 .. LEN_{N-1}      （uint16 BE，逐帧字节数）
[4+2N .. +8)     ORIG_W(2) | ORIG_H(2) | ORIG_BYTES(4)   （都是大端）
[末 2 字节]       LIFT_x10(2)            （uint16 BE，单位 = 0.1 灰度级）
```

**长度判别（按总长 L，严格匹配）**

| L | 含义 | 谁在用 |
|---|---|---|
| `4 + 2N` | 无 ORIG、无 LIFT（最老的格式） | **MODE=2 文字帧用它**（§9 向量 D）；图片会话不用 |
| `4 + 2N + 8` | 有 ORIG、无 LIFT | **2026-10-23 起双方在用的格式** |
| `4 + 2N + 10` | **有 ORIG、有 LIFT** | **本版新增**，待 B 实现 |
| `4 + 2N + 2` | 无 ORIG、有 LIFT | 保留，我方不会发 |

**ORIG 语义**：`N=1` → 这张图的宽高与原始 JPEG 字节数；`MODE=1` → **那张 512 原图**的宽高与字节数（不是分块）；
`MODE=0` 且 `N>1`（多张不同的图）→ **不带** ORIG、也不带 LIFT（带了会误导）。
（注意：`MODE=1` 的 `N=4` 是同一张图分四块，照常带 ORIG 与 LIFT。）

## 7 LIFT：暗部抬升与还原（本版核心）

### 7.1 为什么需要

编码器在**很暗**的画面上残差几乎为 0（实测：全黑图容器 156 B，65,536 个 rANS 符号里只有 31 个非零 = 0.047%），
解码端只能靠模型先验去"猜"，而先验在暗部会给出**偏红**的结果。抬亮之后残差回来了，颜色就正常。

### 7.2 编码端（A）怎么做

1. 把整幅图规整成 512×512（大图）或 256×256（小图），像素值 0~255；
2. 切成四个象限，取**最暗象限的平均亮度** `m_min`；
3. 若 `m_min < 45`（阈值 `GLC_DARK_THRESH`），则取 `K = 60 − m_min`（目标均值 `GLC_DARK_TARGET = 60`，`K` 上限 60）；
   否则 `K = 0`；
4. **对整幅每个像素每个通道加同一个常数 `K`**，`clip(·, 0, 255)`，**不做任何对比度/色相变换**；
5. 用加过的图去编码；`LIFT_x10 = round(K × 10)` 写进 BEGIN 末尾 2 字节。

### 7.3 解码端（B）怎么做

```
解码得到 0~255 的 RGB 之后：
    if LIFT > 0:
        out = clip(out - LIFT, 0, 255)      # 逐像素、逐通道，减同一个标量
```

- 只在 `LIFT > 0` 时做；`LIFT = 0` / 字段缺省时**什么都不做**（与今天的行为完全一致）；
- 减法在 **0~255 空间**做，不涉及 latent、先验、scales。

### 7.4 三条硬约定

1. **大图（MODE=1）整幅只抬一次**，四块共用同一个 `K`，所以 `LIFT` 在 BEGIN 里**只出现一次**；
2. **只有"多张不同的图"（`MODE=0` 且 `N>1`）不使用 LIFT**：各图暗度不同、一个字段表达不了，我方保证此类会话 `LIFT = 0`。
   ⚠️ `MODE=1` 的 `N=4` **不是**"多张不同的图"，而是同一张 512 的四块，**照常带 LIFT**（§9 向量 C）；
3. **过曝不可逆**：抬升时若某些像素被 `clip` 到 255，减回去也回不到原值（这部分本来已接近纯白）。

## 10 B 侧实现清单（三处，都很小）

0. **应答**：每收到一帧（控制帧/数据帧）回 `AA 55 06`（成功）或 `AA 55 15`（失败）。
   ⚠️ 这两个应答**不带 §2 的信封**，就是 3 个字节；
2. **还原**：解码出 0~255 后执行 §7.3 的减法（`LIFT=0` 时跳过）；
3. **记录**：日志/界面里打印 `LIFT=xx.x`，并标注"已按抬升量还原"。

## 11 未验与边界（必须写清）

- **减回后的残余误差未量化**：抬升-编码-解码-减回是一条有损链，最终 PSNR 会在 B 侧降多少，**未验**；
- **抬升目标 60 是否足够不红**：已知 30 会红、102 不红（B/013 实测），60 落在中间，**未做二分标定**；
- **阈值 45 / 目标 60 / 上限 60** 都是当前实现值，可现场调（`GLC_DARK_THRESH` / `GLC_DARK_TARGET`）；
- 本文所有"实测"= A 板命令输出；B 侧的解码结果由 B 侧提供，未在 A 侧复算。
