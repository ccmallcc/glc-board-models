### 1.2 顺带发现一个缓存风险（不是本次的原因，但会造成"发旧容器"）

`ui_send.sh` 的预编码缓存键是：

```bash
PREDIR=/root/pre_enc
_pkey() { printf '%s' "$1" | md5sum | cut -d' ' -f1; }
PRE="$PREDIR/$(_pkey "$IMG")_$(stat -c %Y "$IMG" 2>/dev/null || echo 0).glc"
if [ "$BIG" != "1" ] && [ -f "$PRE" ]; then
  echo "[UI] ② 命中预编码容器 ⇒ 跳过编码：$PRE"
```

**键 = md5(文件完整路径) + mtime 秒**。若同一路径被同名文件覆盖、且 mtime 秒相同（例如 `cp -p`／解压保留时间戳），就会**误命中旧容器**。
本次没有触发（`/root/pre_enc/` 为空），但这类现象值得你们一起留意。

## 4. 决定性线索：**同一条链，有的图能解、有的不能**

同一台板子、同一条编码链，连编 3 张 256×256 图，拿回 PC 用**同一套 int8 `_ZG` 参考链**解：

| 测试图 | 容器 | md5 | 解出 PSNR |
|---|---|---|---|
| t1 = IMG_0036（同像素的 PNG） | **292 B** | `e9b07f13c65186fb461b377b5f024d28` | **8.07 dB**（解不开） |
| t2 = 水平翻转 | **280 B** | `04305fcffd53abc569d0e78dcb861721` | **7.64 dB**（解不开） |
| t3 = +16 亮度 | **316 B** | `3ec81da820a0cc56187411223de041a6` | **21.37 dB**（**解得开**） |

> PSNR 口径：**解码图 vs 该图 256×256 无损 PNG 原图**，峰值 255、整幅 RGB、uint8。
> 解码命令：`pc_decode_selfcontained.py --glc_dir … --png_dir … --n 3 --device cpu`。

三条容器的头部结构都自洽（z 28 B，四段流长度都是 4 的倍数，和 = 载荷长度）。

⇒ **可以排除缓存**（`/root/pre_enc/` 为空）、**可以排除"某一张特定图"**（3 张里 2 张失败）。
⇒ **解码端也可以基本排除**：同一套参考解码器对 t3 解出 21.37 dB，说明解码链本身可用。
⇒ 剩下的嫌疑集中在**编码侧写出的 rANS 字节**。这是**推断**，因果要用 `A/009` 的 PL-vs-CPU 对照来钉死。
⇒ 与你们"292 B → 红图 / 316 B → 正常"**现象一致**。

### 4.1 下一步（我们准备做，先告知）

同一张图分别用 **PL rANS（FPGA）** 与 **CPU rANS（A53）** 各编一次，然后两条都解：

- 若 CPU 版能解、PL 版不能 ⇒ 缺陷锁定在 **PL rANS**；
- 若两版都不能解 ⇒ 锁定在**胶水 / 先验**一侧。
