## 2 我们这边的不确定性：根因与修复（本篇重点）

```
现象：同一容器 dark_BR.glc，换进程/换脚本会得到不同结果：
  · 符号差异数：一处记 57/100/123/132，另一处记 57/144/148/144
  · 一份独立实现把 int8 容器解成【三通道全 0 的纯黑图】（重建里出现 NaN → uint8 全 0；符号本身非零）
  · 复核者另见过某次 max|Δ| 达 1.5e8（是否为 rANS 位流失步尚属【推测】）

定位：训练/推理代码默认 torch.set_num_threads(4) 且启用 MKLDNN，浮点归约顺序随线程调度变化。
修复：torch.set_num_threads(1) + torch.backends.mkldnn.enabled = False + OMP/MKL_NUM_THREADS=1。
验证：同一容器连续三个【独立进程】→ PNG md5 完全相同（BF16 暗块 0cc530b2…；int8 对照 49f94c14…），mean 与符号差异数逐项相同。
注意：这两个 md5 只对 `det_probe.py` 这份配置成立；复核者在「少调一句 use_deterministic_algorithms」的驱动下得到 6ab69adf… / 857aacb5…，均值与符号计数仍全同 ⇒ 可复现的是【数值】，PNG 字节指纹依赖具体配置。
```

**修复后各量的可复现性（按项写，不再笼统说「跨进程」）**

| 量 | 修复前 | 修复后（三次独立进程） |

| int8 容器整图 | 与其他实现不一致 | **本链三次一致**（PNG md5 49f94c14…）；跨实现仍不一致——另一驱动在同设置下依旧是 NaN→全黑图（md5 8b61b39d…） |
| BF16 容器整图 | 不同进程不同 mean | **一致**（PNG md5 0cc530b2…） |
| means（对 mask 16,384） | 曾出现 max\|Δ\| 0.81~1.60 | **一致**：修复设置下重测四个相位 max\|Δ\| = 0.0、n>1e-6 = 0 |
| 符号差异数 | 57/100/123/132 或 57/144/148/144 | **一致**：暗块 57/100/123/132；好块 66/75/72/79 |
