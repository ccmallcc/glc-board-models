# B/015：暗图红的选档方案 —— 用「自解 G/R」当判据（附伪代码、阈值、验收表、日志格式）

## 0 一句话

```
S1 换精度对 B 完全透明（解码端一行都不用改），所以选档可以只做在编码端。
判据不能用「scale 被钳到 0.11 的比例」—— 实测它分不开暗图与好图（60.94% vs 61.06%）；
必须用【自解后的 G/R】。下面是我们建议的落地规格。
```

## 1 为什么不能用钳位比例（先排掉一个诱惑）

| 图 | 全平面 scale ≤0.11 | 占比 |
|---|---|---|
| 暗块 `dark_BR` | 159,751 / 262,144 | **60.94%** |
| 好块 `ctrl_good_TL`（你们 A/014 的数） | 160,068 / 262,144 | **61.06%** |

```
两张几乎一样 ⇒ 钳位比例没有区分力，不能当「该切 int8」的判据。

换一套分母也一样（解码真正用的是 mask 后那 16,384 个）：
  暗块 36,542 / 65,536 = 55.76%
  好块 36,469 / 65,536 = 55.65%
⇒ 两套分母都几乎相同，更说明这个指标不携带区分信息。

（这组聚合计数我们两边逐值相同 ⇒【推断】两侧 S3 同源，未做逐元素比较；
  要强调的是：问题不在算得对不对，而在这个指标不携带区分信息。）
```

## 2 建议的判据：自解一次，看 G/R

（G/R 由未取整的通道均值算出；表中 mean 已取两位小数，直接用两位小数相除会有 ±0.001 差，例如暗块 BF16 的 0.299 与按 8.73/29.25 算出的 0.298）

| 样本（顺序 R / G / B，均为 B 侧 PC 自解） | mean RGB | G/R | 判定 |
|---|---|---|---|
| 好块（BF16） | 67.36 / 61.13 / 89.01 | 0.908 | 正常 |
| 暗块提亮（BF16） | 103.14 / 92.69 / 84.94 | 0.899 | 正常 |
| **暗块（BF16）** | 29.25 / 8.73 / 3.52 | **0.299** | **红** |
| **好块压暗（BF16）** | 20.95 / 2.31 / 9.73 | **0.110** | **红** |
| 暗块（**int8**） | 39.07 / 34.47 / 31.87 | **0.882** | 正常 |

```
正常图 G/R 实测 0.88~0.91；红图 0.11~0.30 —— 中间空档大，阈值取 0.5~0.6 都不敏感。
建议 0.55（离两侧都 >0.25 的余量）。
与 B/013 用的「报红判据 G/R < 0.5」的关系：0.5 是【判定这张已经红了】，0.55 是【选档切换点】，
取 0.55 比 0.5 高一点，是为了在「还没红到 0.5」之前就切档，留出安全余量。
```

## 3 落地规格（编码端，按 256×256 块为单位；512 图 = 4 块各自独立）

```python
def encode_block(img_256, s1_bf16, s1_int8, threshold=0.55):
    glc, y = encode(img_256, s1_bf16)          # ① 默认走 BF16（当前产线档）
    rgb = self_decode(glc)                     # ② 自解一次（pc_decode_selfcontained.py）
    gr = mean(rgb.G) / max(mean(rgb.R), 1e-6)
    if gr < threshold:                         # ③ 只在判红时才换档重编
        glc, y = encode(img_256, s1_int8)
        gr2 = G_over_R(self_decode(glc))
        log(block, s1="int8", gr=gr, gr_after=gr2, md5=md5(glc))
    else:
        log(block, s1="bf16", gr=gr, md5=md5(glc))
    return glc
```

```
代价（以下数字为【估算，未在本机实测】：单帧编码时间按你们 A/014 §2 的 1.05 s/帧量级、自解按 0.3 s 估）：
      正常帧：+1 次自解 ≈ +0.3 s
      判红帧：+1 次自解 +1 次重编 +1 次再自解 ≈ 0.3 + 1.05 + 0.3 ≈ +1.65 s（若重编只需 0.6 s，则约 +1.2 s）
      只有暗帧才付这个代价；具体数请以你们实机为准。
若 0.3 s/帧 也嫌贵：改为「亮度预筛 + 抽样自解」——只对 luma 均值 <70 或暗像素占比 >30% 的块自解。
```

## 7 兜底方案（零模型改动，最保险）

```
编码前黑位抬升：x = clip(x + 18, 0, 255)
【实测（已有证据）】你们 A/014 的 dark_BR_brightened（提亮方式 ×2.2+25）编成容器后，我们自解得到
  mean 103.14 / 92.69 / 84.94、G/R = 0.899 ⇒ 不红。这条是【提亮后重新编码再解码】的实测。
【未验（本封提议的新公式）】黑位抬升 x' = clip(x+18)：对暗源 +18 后应为 55.24/51.12/48.04，
  这个组合我们【从未编码/解码过】，G/R 会不会正常未知。
  ⇒ 若要采用，请先在一张暗图上试编、自解、看 G/R 再推广；不要把它当已验结论。
代价：暗部发灰、观感损失；但不需要改任何模型/精度/解码端
```

## 8 风险与边界

```

  PSNR 口径：255 峰值、整幅 256×256 RGB、uint8，本机 PC 链对源图 JPEG。
```
