# GLC2 验收向量 —— INT8 链

四个 256×256 的 GLC2 容器（312–324 B）＋ 配对的源图与参考解码图。
容器由**板端 INT8 `_ZG` 链**产出，参考解码图由**同一套 INT8 `_ZG` 子图**解出。

```
glc/full_img{0..3}.glc    容器
src/full_img{0..3}.png    源图（编码器的输入）
rec/full_img{0..3}.png    参考解码（解码器的输出，用它比对）
check.py                  Tier 1：查指纹 + 重算 PSNR（零依赖）
verify.py                 Tier 3：比对你的解码输出
MANIFEST.md               全部 md5 与期望值
```

---

## 为什么必须是 INT8

`GLC2` 容器**不存 scales/means**，只存 z 的 16 个索引（28 B）。
解码端必须自己从 `z_hat` 把每个相位的熵参数重新推出来，**而且必须逐位一致**——
rANS 是顺序状态机，第 i 个符号的 CDF 错一格，后面整段就废。

板端编码用的是 **INT8 `_ZG`** 子图。所以：

- 用**同一套 INT8 `_ZG`** 解 → 逐位一致，能解（本目录的 `_rec.png` 就是这么来的）；
- 用 **fp32 PyTorch 参考实现**去解 int8 容器 → 推出来的不是同一套参数 → **全 NaN / 整段崩**。

这不是实现 bug，是格式本身的约束：**容器只能被与它同源的先验路径解开。**
我们的选择是让"同源"落在 **INT8** 上，因为那是板的实际运行形态，也是整数运算、
天然可跨实现复现的那一侧。

## 三档校验

### Tier 1 —— 零依赖，任何人有 Python 就能跑

```bash
python check.py
```

校验 12 个文件的 md5，再用源图和参考解码图重算 PSNR，应得：

```
样本 0  18.19 dB   样本 1  22.99 dB   样本 2  19.79 dB   样本 3  25.42 dB   平均 21.60 dB
```

这一档证明：**你拿到的是同一份文件，公开的码率/质量数字是真的。**
它不解码容器。

### Tier 2 —— 需要 INT8 `_ZG` 模型 + Icraft 运行时

```bash
python3 ../AB板/02_A侧代码/07_解码端/工具/pc_decode_selfcontained.py \
        --glc_dir glc --png_dir src --n 4 --device cuda
```

**只喂 `.glc`**，不喂任何 scales/means 旁路数据，解出来的 `_rec.png` 应与本目录里的
**逐字节相同**。这一档证明：**容器本身是可独立解码的。**

所需模型与常量的 md5 见 `MANIFEST.md` §3/§4。门槛在 Icraft 运行时（私有工具链），
不在数据。

### Tier 3 —— 你自己的解码器

```bash
python verify.py 你的解码.png        # 自动挑最接近的样本
python verify.py 你的解码.png 2      # 指定样本
```

主判据是与 `_rec.png` 的 PSNR：

| PSNR | 判定 |
|---|---|
| ≥ 40 dB | PASS，逐像素基本一致 |
| 32–40 dB | PASS（有差异），通常是 S4 生成器实现不同 |
| < 32 dB | FAIL |

参考尺度：解错一个相位是 ~13–15 dB，完全解不开是 NaN。32 dB 这条线离两边都很远。

## 边界（这些**不**成立，别外推）

1. **不证明"任意实现都能解开 GLC2"** —— 这个命题对 GLC2 格式本身不成立，见上面"为什么必须是 INT8"。
2. **只跑了 4 张图、只跑 `q=0`**。
3. **没逐算子比对全部中间张量**：验的是四个相位的 scales/means（4 样本 × 4 相位，共 65,536/65,536 逐位一致）与端到端 PSNR。
4. **HostBackend == 真板** 只在 s2 的一个输出上做过逐位对照（max|diff| = 0），不能外推。
5. Tier 2 需要私有工具链，外部评审实际上多半只能跑 Tier 1。

## 跑 Tier 2 之前先看这一条

WSL 里的 Windows interop 会**无声消失**，症状是 `icraft-run.exe` 报：

```
cannot execute binary file: Exec format error
```

解码器不会解释这个错误，只会报 `拿到 0 个 v_id`（因为 exe 的 stdout 被吞了）。
遇到过就：

```bash
wsl --shutdown     # 让 /init 自己重新注册 binfmt，别手工注册
```

实测今天（2026-10-25）这个坑出现了两次。

## 旧向量为什么撤掉

`verify/IMG_0036.glc`（308 B）是 **fp32 参考链**产出的。同一个进程里编、同一个进程里解是
26.61 dB，**换一个进程解就是 14.60 dB**（实测，2026-10-25）——
容器里没有先验，而 fp32 侧的先验重算不可跨进程复现。

那组文件已撤回。`rec.png` 本身没错，错的是"它可被独立复现"这个说法。
