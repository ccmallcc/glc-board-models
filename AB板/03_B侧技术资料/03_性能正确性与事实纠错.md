# 性能、正确性与事实纠错

## 1. 数字使用规则

每个数字需要对应版本、输入集、运行后端、计时起止、指标对象和原始证据。电脑CPU、HostBackend、RTL仿真、实现估计和实板分别列示；软件重启内核计时不等于按电源计时；纯解码不等于空口到屏幕延迟；参考实现一致性不等于原图重建质量。

本报告不沿用旧稿“约0.013bit/像素”作为256图总码流bpp。按通常的整张RGB图每个空间像素计算：

`bpp = 8 × 码流字节数 / (宽 × 高)`

312～344B、256×256对应0.03809～0.04199bpp。若再除3为每通道元素的比特数，需明确指标名称，不能称整图bpp。图像原始RGB888压缩比还需要明确容器头/无线封装是否计入。

## 3. 重点纠错表

| 旧材料表述或风险 | 统一后的表述 |
|---|---|
| 312～344B的256图约0.013bit/像素 | 按8×码流字节数/(WH)为约0.038～0.042bpp；每通道元素指标需另命名 |
| PL rANS是整机生产解码器，整链加速21倍 | PL rANS为独立验证成果；生产为PS C rANS+NPU。21倍等需说明软件计时与硬件周期推算条件，不能当整机板测 |
| 时序“完全签核” | 固定内部约束通过；独立IP外部I/O未完全约束，整机集成另验 |
| 0.241W是功耗实测/只有动态功耗 | 是独立IP Vivado总片上功耗估计，Low置信度，分项如上；无整板功耗实测 |
| FPGA工业档已完成 | 实际对应功耗报告为Commercial/Typical，脚本注释不是证据 |
| ±58816超出fp16最大65504 | 58816本身小于65504；后续算子/中间结果是否溢出需对应张量证据，不能用错误大小比较证明 |
| tf32数学上不会溢出 | 较大指数范围降低该类风险，但浮点仍有有限范围；以已测试路径与样例为准 |
| Host仿真对比图证明同码流量化端到端 | 原先逐子图校准/静态灌回图仅作局部误差研究；同码流需独立熵路径与最终张量/PNG对拍 |
| 锁使所有硬件并发不可能 | 锁可超时，调用者需验证held、正确释放并避免旁路访问 |
| rANS再编码相同就证明图像内容正确 | 只证明所选概率模型路径的往返自洽，不能单独排除后端/版本不兼容或源文件已经不同 |
| 接收后MD5能证明空口完全无误 | 还需A发送前摘要；SUM8存在相抵错误反例 |
| 11.149秒为按电源至屏亮 | 软件重启内核起成功推屏时刻；液晶光学亮起与电源前导未一起测量 |
| 当前512和红图均已解决 | 512离线就绪待实板；红图根因待双方同码流/模型核对 |
| 构建manifest的NOT_DEPLOYED否定原生版已装板 | 构建时刻与后续最终审计状态不同；同bit摘要的后续实屏通过回执优先用于当前状态 |

旧材料原件不改写，交付副本仅做凭据脱敏；纠错通过本表、逐份审查记录和证据链接建立。新报告应引用校正后的结论。
