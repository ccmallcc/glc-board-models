## 四、上板

> ### ⭐⭐ 2026-09-22 实测后重写：**开发期根本不用做 BOOT.bin**
>
> 板端 Linux **自带复旦微的 FPGA manager**（`CONFIG_FPGA_MGR_FMQL_FPGA=y`），
> 可以用 `/sys/class/fpga_manager/fpga0/firmware` **在不重启的情况下**把新位流配进 PL。
> **已实测 4 次，全部成功，且加载后 NPU 的 `total_hard_time` 与原来一致（346.73 ms vs 346.75 ms）。**
>
> ⇒ **开发循环 = Vivado 出 `.bit` → 一条命令热加载 → 重跑板端程序**。秒级，不重启、不烧卡、不用调试器。
>
> ```powershell
> python E:\fudanwei\GLC-共享包\工具\hotload_bitstream.py --bit <你的>.bit --board 192.168.1.2 --smoke
> ```
>
> **「换 BOOT.bin」只在交付/固化时才做**（§4.5）。细节见 `上板实施方案.md` §4.3。

### 4.1 开发期主路径：`fpga_manager` 热加载

**唯一需要先准备的东西**：把 `.bit` 转成 `.bin`。

```powershell
python E:\fudanwei\GLC-共享包\工具\bit_to_bin.py  my.bit  my.bin
```

转换规则（**已与板上原厂 `.bin` 逐字节核对，5,980,460 字节 0 处不同**）：
> **`.bin` = 去掉 `.bit` 的头（本例 144 字节） + 按 32 位字做字节反序**

然后热加载（PC 侧脚本会自动做转换 + scp + 触发 + 校验，`--smoke` 还会跑一次 S1 验证）：

| 步骤 | 命令 |
|---|---|
| 一键（推荐） | `python 工具\hotload_bitstream.py --bit my.bit --board 192.168.1.2 --smoke` |
| 板上手工 | `cp my.bin /lib/firmware/` → `bash 工具/板端脚本/hotload_bitstream.sh my.bin` |

**判据**：`state` 仍是 `operating`，且 dmesg 出现
`fpga_manager fpga0: writing my.bin to FMSH FMQL FPGA Manager`。

⚠️ **热加载是整体重配 PL**：正在跑的板端程序会失去 PL，**必须重跑**。

### 4.2 摆好文件（**只在要做 BOOT.bin 时才需要**）

把 `.bit` **拷到 `E:\pl_work\BOOT_Gen\`**，并**命名为 `ai7030_edif_top.bit`**
（要与 `7030ai_psin.bif` 里的名字一致；原来那个同名文件是官方的，覆盖即可）。

✅ **`.bif` 的路径我已经改成我们的了**（原版指向 `C:/Users/admin/Downloads/BOOT_Gen/`）。

### 4.3 Procise → Create Image

打开 **`E:\fudanwei\Procise`**，按教程依次点击 → **Create Image** → 得到 `BOOT.bin`。

### 4.4 ⭐ 先烧官方现成位流验证流程（建议，与我们的设计解耦）

`E:\pl_work\BIT\30tai_lite_detpost\` 里有**官方已编好的 Lite 位流和 BOOT.bin**。
**先用它走一遍 §4.5**，证明"板子 + BOOT.bin 替换流程"没问题。

> 也可以直接拿官方的 `.bit` 走 §4.1 热加载 —— **更快，而且风险为零**（不碰启动分区）。
> 我们已经这么做过：`ai7030_top_disable_icap.bit` 热加载 4 次全部成功。

### 4.5 交付路径：换 `BOOT.bin`（官方两条路）

| 方式 | 做法 |
|---|---|
| **读卡器** | 把 SD 卡插读卡器，**直接替换 FAT 分区里的 `BOOT.bin`**（⚠️ **不要格式化**） |
| **SSH**（板子已在网） | `mount /dev/mmcblk0p1 /root/bits` → 替换 `BOOT.bin` → `reboot`<br>⚠️ **必须先挂载**，直接拷到 `/root/bits` **不生效** |

> ### ⭐ 上 PL 不需要调试器（JTAG 仿真器）
>
> **这两条路就是官方给的全部**，《30TAI使用教程》§3.3 原文：
> > **（1）读卡器** —— 将SD卡插入读卡器，直接替换FAT分区中的BOOT.bin。注意不要格式化磁盘。
> >
> > **（2）SSH连接** —— 通过SSH远程连接开发板（登录账户需为root）。
> > 若BOOT.bin所在的磁盘分区已挂载至目录/root/bits下，可直接替换其中的BOOT.bin文件。
> > 完成替换后，执行reboot命令重启开发板。重启系统后位流生效。
> > 若未挂载，需手动完成挂载……输入以下命令：`mount /dev/mmcblk0p1 /root/bits`。
>
> ⇒ **第（2）条就是"用网口把位流写进 SD 卡"**，一条网线即可，**全程不碰 JTAG**。
>
> **为什么不需要**：PL 是在**每次上电**由 FSBL 从 SD 卡上的 `BOOT.bin` 里取出 `.bit`、
> 经 **PCAP** 推进去的（`7030ai_psin.bif` 里 `[destination_device = pl]` 那一行）。
> 调试器不在这条链路的任何一环。
> —— 板子上有 JTAG（Lite 特性表：`1路PS_JTAG、1路PL_JTAG`，U18/U19 各 20pin），
> 但那是给 **QSPI 固化**和 **ILA 在线调试**用的，**不是上板必须**。

#### 4.5.1 SSH 那条的**逐条命令**（板子 IP 换成本机同网段那个）

```bash
# 0. 板上：确认 FAT 分区在哪儿（看见 mmcblk0p1 带 FAT 字样即可）
fdisk -l

# 1. 板上：挂上 FAT 分区（只有先挂上，替换才生效）
#    ⚠️ 实测：我们板子上【没有 /root/bits 这个目录】，得先 mkdir
mkdir -p /root/bits
mount /dev/mmcblk0p1 /root/bits
ls -l /root/bits/BOOT.bin          # 应该能看到已有的 BOOT.bin

# 2. PC：把新 BOOT.bin 推过去（实测直连千兆 40.2 MB/s，7 MB 约 0.2 s）
scp BOOT.bin root@<板子IP>:/root/bits/BOOT.bin

# 3. 板上：刷盘 + 重启
sync
reboot
```

**板端登录**：`root` / `fmsh`【官方 `系统登录.txt`】。

> ⚠️ **换坏了就起不来** —— 且**恢复靠读卡器，不靠 JTAG**。
> ⇒ ① 手边必须有 microSD 读卡器；② **板上原厂启动分区已经整体备份**：
> `E:\fudanwei\_board_backup\bootfat_20260922\`（md5 与板上逐一核对一致）。
>
> ⭐ **开发期用 §4.1 的热加载就完全不碰启动分区，这个风险等于零。**
