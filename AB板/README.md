## 一、系统一句话

A 板拍照 → 板内 GLC 压缩（NPU 推理 + 自研 PL rANS）→ 19.2 kbps 电台 → B 板常驻接收 → 熵解码 + NPU 重建 → FPGA 原生 1024×600 显示。

## 三、可复现入口

- **A 板代码**：`02_A侧代码/`，按 `01_板端程序`…`13_PC杂项脚本` 分类，`MANIFEST.tsv` 可逐文件核对。
- **模型（ZG330 量化产物，202.8 MB → 压缩 52.3 MB）**：
  <https://github.com/ccmallcc/glc-board-models/releases/tag/v2026.10.24>
  解压后 `md5sum -c md5.txt` 必须 10/10 OK（与板端逐字节一致）。
- **解码一致性校验包**：同仓库 `verify/`（308 B 黄金容器 + 参考解码图 + `verify.py`）。

## 四、已知边界（报告里同样写明，不隐藏）

1. **512 大图未实板**：两端协议已对齐、B 侧电脑复解四象限逐像素匹配、197 条离线断言通过，但**尚未走真实空口与实板拼接验收**。
2. **红图问题未闭环**：B 侧收到过一张解出偏红的图，已定位到"颜色重建每通道仿射常数不一致"方向（PC 参考实现解码正常，PSNR 26.61 dB、R−G=−0.1），但最终根因需两端同码流/模型核对。
3. **B 板纯 PL rANS 为独立研究**：四相位逐符号一致有仿真与综合证据，但生产解码器仍走 PS 上的 C rANS，**未做整机替换验收**。
4. **功耗为估计值**：lite 版无电流监控，只有独立 IP 的 Vivado 功耗估计（0.241 W，低置信度），非整板实测。
5. **启动计时为软件重启计时**，非按电源按钮起计。
